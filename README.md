# Tide · Rust + Next.js 量化交易

Bybit 实盘交易管理平台。后端和交易引擎全部使用 Rust，前端使用 Next.js 静态构建。服务器直接运行二进制程序，通过 systemd 管理；运行时不依赖 Docker、Python、Freqtrade 或 Node.js。

管理后台：[trade.juyouagent.com](https://trade.juyouagent.com)。首次从旧版迁移后交易保持暂停，核对账户和配置后在页面启动。

## 页面分工

- **交易策略**：AI 交易开关与立即分析或复盘、分析间隔、影子模式、复盘学习、事件触发（钩子与 Webhook），以及市场、最高和最低杠杆、交易哪些币和账户级风控（最低置信度、当日亏损、回撤暂停、连续亏损）。
- **知识库**：AI 参考的策略笔记，含预置、手写和 AI 复盘写的观察。
- **决策记录**：每次大模型调用一条，标明触发方式和结果（已执行、拦截、失败、观望），分析过程和技术细节默认折叠。
- **大模型**：API 渠道、服务商、模型、思考参数和 Key。

## 项目结构

```text
backend/src/
  main.rs          服务入口、systemd 信号处理
  api.rs           管理接口、账户、策略设置
  auth.rs          scrypt 密码、HMAC 会话、Origin 检查
  exchange.rs      Bybit V5 签名、行情、下单及成交查询
  engine.rs        仓位、订单恢复、风控、止损
  indicators.rs    EMA / ADX / RSI / ATR
  ai.rs            Anthropic / OpenAI 兼容模型、定时决策
  review.rs        AI 复盘：统计已平仓交易，把观察写入知识库
  hooks.rs         事件触发：持仓/行情事件与外部 Webhook 叫醒 AI，含限频
  knowledge_seed.rs 知识库预置笔记（来自公开策略资料，注明证据强弱）
  store.rs         SQLite 订单、交易、决策和日志
  migrate.rs       旧版配置、登录及历史交易导入
  mcp.rs           MCP stdio 客户端
  tests.rs         模拟交易所及 HTTP 集成测试
web/               Next.js / React / TypeScript 页面
deploy/native/     构建脚本、原生服务、HTTPS 与 443 分流
```

## 架构

```text
浏览器 → Nginx SNI :443 → Caddy HTTPS :8443 → Rust :8000
                                              ├─ Next.js 静态页面
                                              ├─ 管理 / AI / MCP API
                                              ├─ SQLite
                                              └─ Bybit V5 REST
其他 TLS 域名 → 原有 sing-box :8444
```

Next.js 只用于开发和构建。部署包包含一个静态链接的 Rust 程序及 `web/` 静态资源；HTTPS 和分流同样以本机二进制服务运行。

## 本地构建

需要 Rust stable、musl 工具链、Node.js 和 pnpm（仅构建时）。Linux / WSL：

```bash
rustup target add x86_64-unknown-linux-musl
sudo apt-get install musl-tools
bash deploy/native/build.sh
```

产物：`dist/tide-linux-amd64.tgz`。依赖由 `Cargo.lock` 和 `web/pnpm-lock.yaml` 固定。

单独检查：

```bash
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cd web && pnpm install --frozen-lockfile && pnpm build
```

## 原生部署

服务器部署目录 `/opt/tide`，SSH 名称 `s-tokyo`。详细流程见 [部署说明](deploy/README.md)。

后续线上更新在项目根目录的 Linux / WSL 终端运行 `make depoly`（也支持 `make deploy`），自动测试、构建、备份、部署和检查，失败时回退代码。

```text
/opt/tide/bin/caddy             HTTPS 二进制
/opt/tide/releases/<版本>/tide  Rust 二进制
/opt/tide/releases/<版本>/web/  Next.js 静态资源
/opt/tide/current              当前版本软链接
/opt/tide/data/config.json     配置和 API 密钥，权限 600
/opt/tide/data/auth.json       管理员密码哈希，权限 600
/opt/tide/data/tide.sqlite     交易、订单、决策、运行日志
/opt/tide/caddy-data/          HTTPS 证书
/etc/tide/tide.env             环境配置，权限 600
```

服务管理：

```bash
systemctl status tide tide-caddy tide-sni
journalctl -u tide -f
curl http://127.0.0.1:8000/healthz
```

首次初始化新账户：设置 `TIDE_DATA_DIR`、`TIDE_ADMIN_PASSWORD`，执行 `tide init`。密码仅在初始化时需要；已有配置不会被覆盖。

旧版迁移：停止旧引擎并核对所有机器人仓位和挂单后，执行 `TIDE_DATA_DIR=/opt/tide/data tide migrate /opt/tide/user_data`。发现任一旧实盘库有未平仓记录就拒绝导入。导入现货和合约历史交易、登录密码、API Key、Telegram、AI 配置和决策记录，不导入模拟盘记录。旧数据原样保留。

## 策略与交易行为

- AI 使用 4 小时、日线和短周期（1 小时、15 分钟）的收盘 K 线与技术指标进行分析并决定开仓、持有或平仓，短周期用于把握盘中入场时机；系统不再运行独立的均线自动交易策略。
- 默认暂停开仓。暂停时，已有仓位的止损、止盈继续执行。
- 资金分配由 AI 决定：快照给出 `trade_limits.allocatable_usdt`（可用资金预留 5% 后还能投入的保证金），AI 每笔开仓给出 `margin_usdt`，自行在本轮各笔之间分配；超过剩余可投入额会被下调，不给时按剩余名额与实际能支持的笔数平分。仓位 = 保证金 × 杠杆，止损时亏损约为仓位 × 止损距离，**单笔不设亏损上限**，只由账户级风控（当日亏损、回撤、连亏）兜底。最大持仓数只限制同时持仓数量，不要求资金足够开满；最低下单金额和数量以交易所对该币种的要求为准。
- 止损、止盈由 AI 在开仓时设置（止损限制在 2%–10%，缺省为 2.5×ATR；止盈缺省为止损距离的 2 倍），之后 AI 可用 `set_stops` 调整，止损只能收紧。两次分析之间，价格走出一个止损距离后，系统按止损距离的一半追踪止损作保底。方向、同时持仓数量、仓位大小和杠杆都由 AI 决定，页面上没有对应开关：同时最多 5 笔（代码常量 `MAX_OPEN`），杠杆不超过最高杠杆、交易所上限和保证止损先于强平的安全值，超出上限的请求会被下调而不是拒绝；「交易策略」页可设最低杠杆（默认 1 倍，合约有效），AI 选得更低会被抬到最低杠杆，但止损较宽、安全值低于最低杠杆时以安全值为准；修改最低杠杆只影响新开仓，不需要先平仓；快照会告诉 AI 每个币的最小下单额和按安全杠杆所需的最少保证金。保证金不变时，杠杆越高仓位越大，止损时亏得越多。
- 风控熔断：账户回撤超过上限（默认 20%）自动暂停机器人；连续亏损达到上限（默认 5 笔）停止开仓。每次启动机器人会重置回撤基线和亏损计数。「AI 交易」页可开启「影子模式」，只记录决策不下单。
- 市价单执行；交易所可能部分成交或拒绝成交。确认实际成交数量、价格和手续费后才更新本地仓位。
- 下单前将唯一订单号持久化。超时先核对成交，不盲目重发。存在待确认订单时禁止新开仓，重启后继续核对。
- 所有下单入口串行检查持仓、资金和风控。AI 自动执行和手动分析执行采用相同置信度限制；外部明确下单不接收模型置信度。
- 合约支持设置 1–25 倍杠杆，并校验交易对在交易所的杠杆上限；现货保持 1 倍。合约要求 Bybit 统一账户使用逐仓、单向持仓模式。合约止损挂在交易所，并同步实际平仓；不合并已有的手动合约仓位。
- 现货止损挂成 Bybit 条件单（卖出前先撤单），挂单失败时由 Rust 服务按价格监控；现货止盈由服务监控，服务关闭期间无法执行。现货平仓精度以下余额记为零碎余额，仍可在 Bybit 账户中查看。
- AI 主动平仓：开仓不足 60 分钟（代码常量 `MIN_HOLD_BEFORE_AI_CLOSE_MINUTES`）时系统拒绝 AI 的 `close`，止损照常生效，AI 可用 `set_stops` 收紧止损；通过接口或 MCP 手动平仓不受限制。快照里每笔持仓带 `held_minutes`，`exit_performance` 按出场方式汇总最近 50 笔平仓（`force_exit` 即 AI 主动平仓），提示词要求 AI 只在点明开仓逻辑失效时平仓，接近止损、可能反弹或小幅浮亏交给止损处理。
- 自动交易只由 AI 决策，不再运行均线策略；不限制每日开仓次数。平仓释放名额后，AI 可继续开多或开空（需允许做空）。待确认订单仍会阻止新开仓，当日亏损和置信度限制继续执行。
- AI 以账户净盈利增长为目标，结合手续费、滑点与适用的资金费评估交易机会；根据后续预期收益判断开仓、持有和平仓，不以单笔回本为目标。分析须说明具体行情依据。当日亏损、回撤和连亏上限只由系统执行，不发给 AI，AI 也不应因此缩小仓位或放弃机会；触及上限时系统直接拦截新开仓。可在「交易策略」页设置每日盈利目标（占当日起始权益的百分比，默认不设），AI 只看到目标、今日已实现盈利和还差多少，亏损日的已赚金额显示为 0。缺乏正预期收益依据时可以不交易。

实盘汇总以本地记录的成交和交易费用为基础，不能代替交易所账单（例如合约资金费及外部交易会影响账户权益）。

## AI 与外部接入

接口地址填根域名时，OpenAI 兼容模式会自动补 `/v1`（例如 `https://api.onerouter.com` → `/v1/responses`）；完整端点与自定义路径前缀保留原路径。所有模型请求明确使用非流式 JSON；收到 HTML 网页会提示实际请求地址，避免误报为模型回答的 JSON 格式错误。

OpenAI 兼容模式可选择 Chat Completions 或 Responses，以及模型支持的思考等级。旧配置默认 Chat Completions、思考等级为“服务商默认”（不传参数），不会自动切换接口或提升等级。Responses 使用 `reasoning.effort`，Chat Completions 使用 `reasoning_effort`；不支持的参数会显示服务商错误。Claude 使用 Messages 接口，可独立配置自适应思考、手动预算或关闭（以模型支持为准），思考等级通过 `output_config.effort` 发送；手动预算为 1024–15999 tokens，总输出上限保持 16000。旧配置不额外传参，保留服务商默认行为。地址可填写服务商基础地址或完整端点；模型输出不完整或拒绝生成时不执行交易。

AI 支持 Anthropic 和 OpenAI 兼容接口。分析间隔可自定义为 1–1440 分钟，另可设置计划时间后的延迟秒数（必须小于间隔）；默认每 4 小时、延迟 180 秒。按固定时间轴对齐，下次运行时间显示在页面；修改后从下一个计划时间生效，不立即补跑。行情使用 4 小时已收盘 K 线。知识库页面可增删改策略笔记并单独启用或停用，启用的笔记（总量上限 24000 字）随每轮快照作为参考发给模型，模型被要求只把它们当启发、不得覆盖风控，并在分析里说明参考或否决了哪几条；首次启动会预置 7 条笔记，删除后不会再自动恢复。AI 复盘学习（默认开启）：新平仓 3 笔后，或 1 笔且距上次复盘满一天，AI 会读取胜率、盈亏比、各出场方式、币种方向和持仓时长的统计与最近 40 笔交易，把有数据支持的观察以“AI 观察”笔记写入知识库；它最多维护 12 条、只能增改删自己写的笔记，预置和手写的笔记不可改。复盘结果记录在「决策记录」页，也可手动点“立即复盘”。使用 Claude 模型时自动启用提示词缓存：知识库和各币种的 K 线历史（收盘后才变）排在前面并打上缓存标记，账户、持仓、`exchange_live`、触发原因等每轮都变的内容排在后面，所以命中的部分只按约 1/10 价格计费，输出不变；分析间隔 5–59 分钟用 1 小时有效期，短于 5 分钟用 5 分钟，达到 1 小时或更长时不写缓存（下一轮读不到，写入反而多花钱），命中、写入和未缓存的 token 数显示在决策记录里，决策记录页顶部还按天汇总最近 14 天的调用次数（含失败和各触发方式）、输入、缓存命中率和输出 token，只统计 token，不换算金额。分析间隔设为 240 分钟、延迟 180 秒即与 4 小时 K 线收盘对齐（按 UTC 整点计时），交易策略页有一键预设；两次分析之间的异常靠事件触发。OpenAI 兼容接口不由我们控制缓存，沿用服务商的自动缓存。每轮请求仍是全新对话，连续性靠快照里的 `previous_runs`（最近 3 轮的分析、模型留给自己的笔记和动作结果）与每笔持仓的开仓理由，模型被要求没有新证据就不翻转既有计划。模型请求期间不锁住止损线程，执行前重新读取风控状态；分析未结束时不会并发运行另一轮。

各币种的行情并行读取；读不到行情统计时会单独再取一次现价，仍失败则 `last_price` 为空，AI 被要求本轮不对该币开仓或改止损。决策记录保留 90 天、运行日志保留 30 天，启动时和写入过程中自动清理；交易、订单和知识库不会被清理。每个币的快照还带实时的 `market_stats.last_price`（及买一卖一价）和尚未收盘的 4 小时 K 线 `forming_4h_candle`，K 线与指标仍只用已收盘的；提示里要求 AI 以 `last_price` 作为现价，不再靠涨跌幅估算。每轮快照还带 `exchange_live`：分析时实时向 Bybit 读取的全部持仓（杠杆、强平价、保证金、浮盈、止损止盈）和挂单，其中你在交易所手动开的仓位和下的单会标明不归 Tide 管理，AI 只能把它们当作已占用的保证金和已有的敞口来参考，不能操作；读取失败时会如实告知 AI，此时它只管理现有止损、不开新仓。账户里的 `available_usdt` 是扣除保证金和挂单后真正可用的余额。

Telegram 通知：开仓、平仓、止损成交、熔断照常发送；AI 决策只在有动作（已执行、风控拦截或失败）时发一条简短摘要，注明触发方式，观望的轮次不打扰；模型调用出错只在从正常变为出错时提醒一次，不会每轮重复。

事件触发（钩子，默认关闭，在「交易策略」页配置）：除定时分析外，下列事件会让 AI 提前分析一次，快照里的 `trigger` 会写明原因。内置事件：持仓浮亏走到当前止损距离的 60%（止损被 AI 收紧或上移后按新的止损位算，止损已到盈利一侧则不再提醒）、浮盈走出一个止损距离、仓位被交易所止损或止盈平掉（不含强制平仓）、所选币种一小时内波动达到设定百分比（同一币两小时内最多一次）。事件触发的分析同样走完整的风控，两次分析至少间隔 5 分钟（可设），事件触发的分析每小时最多 6 次（可设），排队的事件合并成一次分析，定时分析开始时一并覆盖。外部 Webhook：在「交易策略」页生成地址 `POST /api/hook/<密钥>`（完整地址只显示一次，可重新生成或停用），请求体可以是纯文本、`{"message": "..."}`，也可以是不含 message 的 JSON（如 TradingView 的 JSON 告警，整段内容会交给 AI），例如 `curl -X POST -d "BTC 突破前高" https://你的域名/api/hook/<密钥>`。该接口不需要登录，只靠密钥访问，密钥用常量时间比较，猜错每分钟超过 10 次会被限速，每小时最多接受 30 条；消息只作为不可信的线索交给 AI，不能下单，也不能改变任何限制。

所有 API 先 `POST /api/auth/login`（JSON `username` / `password`）获取会话 Cookie。写请求必须带与 `TIDE_PUBLIC_ORIGIN` 相同的 `Origin`。Basic Auth 已移除。

- `GET /api/ai/snapshot`：行情和持仓快照。
- `POST /api/ai/order`：`{"action":"open_long|open_short|close","pair":"BTC/USDT","reason":"…"}`。
- `POST /api/ai/run?execute=false`：分析；`true` 会按风控执行。
- `GET /api/orders/pending`：待核对订单。结果不确定时不要手动重复下单。
- `GET /api/ai/log`：决策记录。

Rust 程序同时提供 MCP stdio 模式，不需要 Python：

```bash
claude mcp add tide-trade -e PANEL_PASS=后台密码 -- /path/to/tide mcp
```

可选环境变量：`PANEL_URL`、`PANEL_USER`。MCP 客户端自动登录、保存会话并发送正确的 Origin。Linux 发布包用于 Linux；Windows 本地 MCP 需要通过 WSL 运行，或用 Cargo 构建对应平台二进制。
